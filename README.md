# عقاري برو | الإصدار الأول لأصحاب العقارات

## 🚀 تشغيل النسخة الكاملة على GitHub

**[افتح Aqari Pro مباشرة في GitHub Codespaces](https://codespaces.new/SulaimanAlsanani/aqari-pro?quickstart=1)**

عند اختيار **Create codespace** يبدأ تجهيز Laravel 12 وPostgreSQL 16 تلقائيًا عبر Docker. افتح تبويب **PORTS**، ثم المنفذ **8080**، وانتقل إلى `/staging/` من رابط GitHub الآمن. **احتفظ بمنفذ Codespaces على Private.**

لإنشاء أول حساب مالك تجريبي من Terminal داخل Codespace:

```bash
docker compose --env-file backend/deploy/local/.env.local -f backend/deploy/local/compose.yaml exec app php artisan aqari:provision-owner owner@example.com --name="Test Owner"
```

هذا تشغيل حقيقي للـBackend داخل **بيئة تطوير مؤقتة**، وليس استضافة إنتاجية دائمة. أما [GitHub Pages](https://sulaimanalsanani.github.io/aqari-pro/) فيستمر بتقديم الواجهة الثابتة المنفصلة. التفاصيل في [دليل Codespaces](.devcontainer/README.md) و[التشغيل المحلي](backend/deploy/local/README.md).


هذا المشروع **نسخة تجريبية للمالك الذي يدير عقاراته بنفسه**، وليس نظامًا مخصصًا لمكاتب إدارة الأملاك.

## نطاق الإصدار الأول
- ملف مالك واحد ومحفظته العقارية.
- العقارات والوحدات وحالات الإشغال.
- المستأجرون والعقود وجدولة الاستحقاقات.
- التحصيل والدفعات الجزئية وسندات القبض.
- المصروفات والصيانة والموردون والوثائق.
- التقارير المالية ولوحة القيادة والتنبيهات.
- مركز **محاكاة** للتكامل مع منصة إيجار، دون اتصال حكومي حقيقي.
- محفظة كبيرة من البيانات الوهمية لمالك واحد، ويمكن إعادة تهيئتها من الإعدادات بعد تصدير نسخة احتياطية.

## الإصدار الثاني المخطط: مكاتب إدارة الأملاك
يدعم عدة ملاك ومحافظ مستقلة، الصلاحيات بين المكاتب والملاك، عقود الإدارة، أتعاب إدارة الأملاك، تسويات الملاك والتقارير المجمعة. ليس جزءًا من الإصدار الأول.

## مرفقات الوثائق
- يمكن رفع ملفات PDF والصور وWord وExcel وCSV وTXT لكل سجل مرتبط بالعقار، بما يشمل ملف المالك والعقار والوحدة والمستأجر والعقد والاستحقاق وسند القبض والمصروف والصيانة والمورد والوثيقة والفحص والمهمة.
- تُحفظ الملفات في IndexedDB داخل المتصفح، مع إمكانيات التنزيل والحذف، بحد أقصى 10 ميجابايت لكل ملف.
- لا تُرسل المرفقات إلى GitHub أو إلى أي خادم، ولا تنتقل تلقائيًا بين الأجهزة.
- النسخ الاحتياطي JSON يقتصر على البيانات النصية ولا يشمل ملفات المرفقات. يجب تنزيل المرفقات المهمة منفردة.
- إعادة تحميل البيانات التجريبية تمحو البيانات المحلية والمرفقات بعد موافقة صريحة.
- **لا تُستخدم النسخة العامة مع هويات أو صكوك أو عقود حقيقية أو أي مستندات حساسة** حتى إضافة حسابات آمنة وتخزين خادمي مشفر وتحكم في الصلاحيات ونسخ احتياطي.

## بدء تأسيس Backend الإنتاجي (غير منشور)
أضيف مجلد `backend/` يحتوي على **أساس Laravel 12**: مخطط PostgreSQL للعقارات والوحدات والمستأجرين والعقود والاستحقاقات والمدفوعات، ونماذج Eloquent، وواجهات عقارات تتطلب `auth:sanctum` وتستمد ملكية العقار من المستخدم الموثق، واختبارات عزل الملاك.

**أصبح بالإمكان تشغيل Laravel وSanctum وPostgreSQL معًا عبر Docker** داخل Codespaces أو على الجهاز المحلي باستخدام الملفات الموجودة في `backend/deploy/`. راجع [دليل Codespaces](.devcontainer/README.md) و[دليل Backend](backend/README.md). تظل GitHub Pages واجهة ثابتة منفصلة لا تتصل بالـBackend.

يتضمن مسار نشر GitHub Pages الملفات العامة المصرح بها فقط، ولا ينسخ مجلد Backend إلى حزمة الموقع المنشورة.

## ملاحظات مهمة
- بيانات الإصدار الحالي محفوظة محليًا في المتصفح، وليست في قاعدة بيانات مركزية.
- بيانات العرض وهمية، ولا تُدخل بيانات شخصية حقيقية.
- تحديث الإصدار لا يستبدل بيانات المتصفح السابقة تلقائيًا.
- لا يوجد تسجيل دخول إنتاجي أو تكامل فعلي مع منصة إيجار.
- التشغيل التجاري يتطلب خادمًا آمنًا وقاعدة بيانات ومصادقة وصلاحيات ونسخًا احتياطية.

## الملفات
- `index.html`: الواجهة وخط Cairo والهوية البصرية.
- `app.js`: وظائف الإدارة والبيانات التجريبية.
- `attachments.js`: مرفقات السجلات عبر IndexedDB.
- `.github/workflows/deploy.yml`: نشر GitHub Pages.
