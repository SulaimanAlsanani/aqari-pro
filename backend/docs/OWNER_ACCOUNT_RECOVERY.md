# Aqari Pro — إدارة حساب المالك واستعادة كلمة المرور

## آلية الحسابات

- ينشئ المشغّل حساب المالك الأول من الطرفية الخاصة باستخدام `php artisan aqari:provision-owner`. لا توجد واجهة تسجيل عامة تسمح لأي زائر بإنشاء حساب مالك.
- بعد تسجيل الدخول، تعرض واجهة Staging ملف حساب المالك وتتيح تعديل **الاسم ورقم التواصل فقط**، بينما يبقى البريد الإلكتروني المرتبط بالحساب ثابتًا (تغييره يحتاج لاحقًا إلى مسار تحقق مستقل).
- تغيير كلمة المرور يتطلب كلمة المرور الحالية وكلمة جديدة مؤكدة لا تقل عن 12 حرفًا، مع أحرف كبيرة وصغيرة وأرقام ورموز.
- عند تغيير كلمة المرور أو استعادتها، تُحذف جلسات المستخدم المخزنة في قاعدة البيانات وتُلغى رموز الاستعادة السابقة. لا تؤثر العملية على ملاك آخرين.
- بيانات الملاك يحددها الخادم من جلسة المستخدم؛ لا يُقبل `owner_id` مقدّم من الواجهة.

## استعادة كلمة المرور

1. يطلب المالك رابط الاستعادة من واجهة تسجيل الدخول.
2. يستخدم الخادم Laravel Password Broker الذي يخزن **بصمة الرمز** في `password_reset_tokens` ويتولى صلاحية الرمز ومعدل إعادة إصدار الروابط.
3. لا يختلف الرد المرسل للواجهة سواء كان البريد مسجلًا أم غير مسجل، لتقليل تسريب وجود الحسابات.
4. يُرسَل الرابط إلى صفحة Staging نفسها باستخدام جزء URL بعد `#`؛ لا يصل هذا الجزء إلى خادم HTTP في الطلب العادي. تمسحه الواجهة فور قراءته من شريط العنوان.
5. يرسل المستخدم الرمز مرة واحدة عبر POST محمي بـ CSRF مع كلمة المرور الجديدة.
6. لا يعاد استخدام الرمز بعد نجاح التغيير، ويُطلب تسجيل الدخول مجددًا.

## تهيئة البريد قبل الاستخدام

**الاستعادة غير مفعّلة فعليًا على أي خادم لم يُربط بمزوّد SMTP مشفّر.** عند ضبط `MAIL_MAILER=log` أو `array` في بيئة Staging غير اختبارية يرفض الخادم طلب إرسال الرابط برمز 503، حتى لا يُكتب رمز الاستعادة في السجلات.

في ملف إعدادات Docker الخاص على الخادم فقط:

```dotenv
AQARI_MAIL_MAILER=smtp
AQARI_MAIL_SCHEME=smtps
AQARI_MAIL_HOST=smtp.your-provider.example
AQARI_MAIL_PORT=465
AQARI_MAIL_USERNAME=your-private-service-account
AQARI_MAIL_PASSWORD=from-private-secret-store
AQARI_MAIL_FROM_ADDRESS=no-reply@your-verified-domain.example
```

استخدم مزود بريد موثوقًا ونطاق إرسال موثقًا (SPF/DKIM/DMARC) وصلاحيات لا تتجاوز الإرسال. يجب أن يدعم الخادم SMTPS/TLS فعليًا وأن تُختبر الرسائل من حساب تجريبي قبل تفعيل الميزة للملاك. لا تحفظ كلمات مرور SMTP أو روابط الاستعادة في GitHub أو محادثات الدعم أو سجلات الأخطاء.

المسارات:

| المسار | نوع الطلب | الحماية |
|---|---|---|
| `POST /forgot-password` | طلب رابط | CSRF + حد 3 طلبات/دقيقة، رد لا يميز الحسابات |
| `POST /reset-password` | استبدال كلمة المرور | CSRF + حد 5 طلبات/دقيقة + رمز يستخدم مرة واحدة |
| `GET /api/v1/account` | قراءة حساب المالك | Sanctum |
| `PATCH /api/v1/account` | تعديل الاسم والهاتف | Sanctum + CSRF |
| `POST /api/v1/account/change-password` | تغيير كلمة المرور | Sanctum + كلمة المرور الحالية + CSRF |

**القيود المتبقية:** MFA، تحقق البريد عند التغيير، آلية دعوة الملاك، وإشعارات العمليات الحساسة وتدقيق أمني خارجي. عدم إتمامها يعني أن نظام الحسابات لا يزال إصدار Staging.
